# Репозиторий для внеплановой проверки случайно выбранных студентов группы M3135 потока y2025 ФиТИП ИТМО

## Симулятор студента на курсе «Введение в программирование»

Это занятие для групповой работы. Вам предлагается реализовать симулятор студента.

Класс Student должен эмулировать действия студента на курсе «Введение в программирование». Класс Student должен реализовывать интерфейс Programmer. В любой реализации интерфейса должны быть известны характеристика владения Java и запас вайба. Доволнительно у любого студента должны быть известны его баллы. Все значения меняются в зависимости от случающихся со студентом событий (интерфейс Event). Любое событие должно иметь возможность подробно его описать (и узнать подробности методом getDetails()). 

События должны покрывать следующие случаи (допустимо сделать больше):
  * Получение домашнего задания одного из следующих типов сложности. Необходимо иметь минимум три, например: Complexity.HARD, Complexity.NORMAL, Complexity.EASY
  * Крепкий сон
  * Смена приоритетов

Домашнее задание всегда может быть вполнено с некоторой вероятностью, и она тем выше, чем выше характеристика владения Java. Если домашнее задание выполнено, оно положительно влияет на вайб, иначе негативно. Попытка выполнить домашнее задание благотворно сказывается на характеристике владения Java, а мера изменения зависит от сложности задания.

Событие второго типа вынуждает пропустить следующее событие, но значительно повышает вайб.

Событие третьего типа случайным образом незначительно влияет на вайб, заставляет пропустить следующее событие и негативно сказывается на владении Java.

Если в результате первого события домашнее задание было выполнено, студент может попробовать сдать его преподавателю (класс Instructor, реализующий интерфейс Programmer). Это дополнительно увеличивает характеристику владения Java. если у преподавателя она выше, чем у студента. Процесс сдачи должен удовлетворять следующим правилам:
  * Чем больше разница во владении Java у преподавателя и студента, тем сложнее сдать задание
  * Количество попыток не превышает 4 и определяется случайно, с зависимостью от сложности сдачи задания
  * Чем больше попыток сдачи, тем ниже полученный балл (но он никогда не будет отрицателен)
  * Если потребовалось 4 попытки, задание не сдано. В таком случае студент тильтует и теряет значительное количество вайба
  * Если задание сдано, вайб студента увеличится
  * С некоторой вероятностью студент будет хукнут Георгием Александровичем (реализация класса Instructor). В таком случае применяются стандартные правила проверки, но владение Java у Георгия Алекснадровича максимальное из возможных.

Обратите внимание:
  * Если вайб студента опустится до определенного граничного значения, он впадет в тильт возьмет ПСЖ
  * Если баллы студента не достигнут определенной отметки, он будет вынужден писать 3 попытки экзамена. Они негативно сказываются на вайбе, а в остальном повторяют событие "Получение домашнего задания средней сложности" без очной сдачи преподавателю
  * Если характеристика владения Java и вайб будут достаточно высоки, студент рискнет сыграть на баллы с Георгием Александровичем. Это соответствует одной попытке сдачи ему задания высокой сложности, с одной попыткой и с большим количеством разыгрываемых баллов. Характеристика владения Java не меняется. Отрицательный исход не меняет вайб, а положительный устанавливает максимальное его значение.
